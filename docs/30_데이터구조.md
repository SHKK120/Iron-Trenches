# 데이터 구조

현재 책임 후보는 구현 전 최종 API가 아닌 `[제안]`이다.

## RTS Core 후보

```text
FactionDefinition
SectorDefinition / SectorState
StrongpointDefinition
BuildingDefinition / BuildingState
ResourceDefinition / EconomyState
ProductionDefinition / ProductionQueue
ResearchDefinition / ResearchState
SupplyNode / SupplyConnection / SupplyState
SquadDefinition / PlatoonState
UnitDefinition / SoldierState
CapitalOrCoreRegion
MatchState
```

## 전선 전투 후보

```text
WeaponDefinition
CoverDefinition
MoraleDefinition
BattleScenario
```

## 책임 경계

- Sector는 소유권, 거점, 경제 가치, 건물과 보급 연결을 연결한다.
- Squad / Platoon은 명령, Formation, 목표, Morale과 Supply State를 소유한다.
- Soldier는 Squad 의도를 표현하는 local movement, 사격, 피격과 시각 상태를 담당한다.
- 일반 건물의 Sector 점령 이전과 적 유닛 / 참호 예외를 데이터와 코드에서 구분할 수 있어야 한다.

## 원칙

- 실제 수치와 콘텐츠 값을 문서나 코드 여러 곳에 중복하지 않는다.
- `[시험값]`은 쉽게 바꿀 수 있어야 한다.
- 프로토타입의 작은 데이터 수가 최종 게임 규모를 제한하지 않는다.
- HTML Prototype의 고정 Build Slot, 임시 수치, Canvas 객체와 AI 구조를 정본으로 복사하지 않는다.
- ScriptableObject와 DOTS 사용 시점은 자동 확정하지 않는다.

## 현재 구현 사실

- `Game/Assets/Scripts/Core/CommandOrder.cs`: Unity API 비의존 `Move` / `AttackMove` 명령 계약과 월드 X/Z 목적지
- `Game/Assets/Scripts/Core/SectorState.cs`: Sector 식별자와 현재 소유 진영, 명시적 소유권 이전
- `Game/Assets/Scripts/Core/SectorTopology.cs`: 비어 있지 않은 Sector 등록, 중복 없는 양방향 인접 관계와 조회
- `Game/Assets/Scripts/Core/SectorCapture.cs`: 완료된 점령의 소유권 적용과 이전/신규 소유자 및 변경 여부 결과
- `Game/Assets/Scripts/Core/FrontlineEdge.cs`: 방향과 무관한 두 Sector 경계 식별자
- `Game/Assets/Scripts/Core/FrontlineResolver.cs`: 현재 소유권과 인접 관계가 다른 경계를 전선으로 즉시 파생
- `Game/Assets/Scripts/Core/SectorControlAnchor.cs`: 별도 Owner 없이 Sector 소유권을 대표하는 Anchor ID ↔ Sector ID 연결
- `Game/Assets/Scripts/Core/TerritoryGraph.cs`: Topology, SectorState와 Sector별 단일 Control Anchor를 연결하고 Anchor 점령·현재 Frontline·Territory 조회를 조정
- `Game/Assets/Scripts/Core/SectorIncomeProfile.cs`: Sector별 0 이상의 단일 시험 경제 가치; 현재 Owner 상태와 분리
- `Game/Assets/Scripts/Core/EconomyState.cs`: 진영 ID와 0 이상의 현재 시험 Balance; 음수 금지, 자금 확인과 실패 시 불변인 명시적 지출
- `Game/Assets/Scripts/Core/SectorIncomeResolver.cs`: Territory의 현재 Sector Owner와 Sector별 정확히 1개 Profile에서 진영별 1회 수입을 파생
- `Game/Assets/Scripts/Core/SectorIncomeCollector.cs`: Timer 없이 명시적 1회 수입을 EconomyState에 적립하고 이전/신규 Balance 결과 반환
- `Game/Assets/Scripts/Core/BuildingDefinition.cs`: Building Type ID, 0 이상의 시험 Cost와 유한한 양수 Footprint Radius
- `Game/Assets/Scripts/Core/BuildingPlacementRequest.cs`: Site ID, Builder Faction, 명시적 Target Sector, Building Type과 기존 `WorldPoint` 위치
- `Game/Assets/Scripts/Core/ConstructionSite.cs`: Type/Owner/Sector를 구분하고 검증을 통과한 자유 WorldPoint와 Footprint를 보존
- `Game/Assets/Scripts/Core/ISectorPlacementAreaResolver.cs`: Point가 속한 Sector와 전체 Footprint의 Target Sector 포함 여부를 Unity와 분리해 판정하는 계약
- `Game/Assets/Scripts/Core/BuildingPlacementResult.cs`: 성공 Site·지출·이전/신규 Balance 또는 구분 가능한 실패 이유
- `Game/Assets/Scripts/Core/BuildingPlacementService.cs`: Target Sector 존재/소유권, 실제 위치, 전체 Footprint, Site 충돌과 자금을 순서대로 검증하고 성공 시에만 지출·Site 추가
- `Game/Assets/Scripts/Core/BuildingState.cs`: 완공된 일반 건물의 ID, Type, 현재 Owner, 설치 Sector, Position과 Footprint; 소유권 이전 시 SectorId와 공간 정보 유지
- `Game/Assets/Scripts/Core/ConstructionCompletionResult.cs`: 명시적 완공 성공 시 완료 Site ID와 Building, 실패 시 원인을 구분
- `Game/Assets/Scripts/Core/ConstructionCompletionService.cs`: Site/Building 목록을 사전 검증하고 성공 시 ConstructionSite 하나를 제거해 같은 Type/Owner/Sector/Position/Footprint의 BuildingState 하나로 전환
- `Game/Assets/Scripts/Core/TerritoryBuildingOwnershipService.cs`: 기존 Anchor Capture를 재사용하고 실제 점령 변경 시 해당 SectorId의 완공된 일반 Building Owner만 새 소유자로 이전하며 변경 Building ID를 반환
- `tools/ManagedPcChecks`: 위 순수 C# Core를 Unity Editor 밖에서 컴파일하고 Anchor 점령→Frontline 이동→수입 증가→Sector 범위 자유 건설을 포함한 불변조건을 확인
- `previews/RTS_CORE_01C_Territory.html`: Territory Graph 개념의 조작·가독성·방향 확인을 위한 비정본 사람용 Playable Preview
- `previews/RTS_CORE_02A_Economy.html`: 단일 자원 시험 구조에서 Sector 점령과 명시적 Collection의 관계를 확인하는 비정본 Preview
- `previews/RTS_CORE_02B_FreeConstruction.html`: Sector 선택, 자유 Ghost 위치, Footprint/충돌/자금 판정과 Site의 Sector 소속을 확인하는 비정본 Preview
- `previews/RTS_CORE_02C_ConstructionOwnership.html`: 현장의 명시적 완공과 Sector 점령에 따른 일반 건물 Owner 이전·Sector 불변을 확인하는 한글 비정본 Preview
- `previews/index.html`: 게임 규칙을 복제하지 않고 현재/완료 Preview 링크와 상태만 제공하는 Hub

이는 관리형 PC용 Source-Only 기술 기준선이다. 모든 일반 `ConstructionSite`와 완공 `BuildingState`는 정확히 하나의 `SectorId`를 가지며 `OwnerId`와 책임을 분리한다. 완공은 Site의 Sector/Owner/공간 정보를 그대로 보존하며, 완공된 일반 Building은 해당 Sector의 실제 점령 변경 때 Owner만 이전한다. 이 이전 계약은 Barracks/Depot 같은 일반 건물에 한정하며 적 Unit·Trench·Defense Facility나 미완공 ConstructionSite 처리까지 일반화하지 않는다. 미완공 Site 함락은 Q-012, 고립 방어시설은 Q-007이 소유한다. 사각형 Sector Fixture와 원형 Footprint는 `[시험 구현]`이며 최종 Geometry/Collider가 아니다. Anchor Owner, Income Owner와 Frontline flag/cache/event는 저장하지 않는다. Browser Preview의 JavaScript는 게임 기술 정본이 아니다. 현재 단일 Income/Balance와 건물 Cost는 `[시험 구조/시험값]`이며 최종 국가 경제나 자원 종류를 확정하지 않는다. 자동 지급 주기, 건설 시간/진행, 건물 재가동 시간, 생산/연구, HP/파괴/수리, 보급/수도와 Unity Component 연결은 구현한 것이 아니다.
