# 환경 복구

군 싸지방처럼 세션 종료 또는 재부팅 뒤 PC가 초기화되는 환경에서, 로컬 상태에 의존하지 않고 저장소만으로 개발을 다시 시작하기 위한 Recovery Runbook이다.

## 문서의 역할

프로젝트를 시작하거나 초기화 PC에서 개발 환경을 복구할 때 필요한 실제 확인값과 운영 절차를 관리한다. 계획값을 사실처럼 고정하지 않고, 확인된 환경값을 누적한다.

## 이 문서가 소유하는 정보

- Repository / Clone과 실제 프로젝트 경로
- 엔진, Package와 로컬 도구의 정확 버전
- MCP 및 `.codex` 로컬 설정 복구
- Project Skill 복구
- 프로젝트 실행, 기계적 Smoke와 원격 Checkpoint 확인
- 초기화 PC 재개 절차와 보안 경계

## 이 문서가 소유하지 않는 정보

- 게임 플레이 규칙과 실제 전투 수치
- 현재 구현 순서와 다음 행동
- 사람의 재미 판정

## 복구 모델

- 로컬 디스크, `.git`, Git credential, Codex 개인 설정과 도구 설치는 언제든 사라질 수 있다고 가정한다.
- 복구 가능한 작업의 기준은 승인된 원격 경로에 남은 마지막 검증 Checkpoint다.
- 작업 종료 전에는 복구에 필요한 코드, 문서, 버전 고정 파일과 스크립트를 Checkpoint에 포함한다.
- 커밋되지 않았거나 push되지 않은 작업은 PC 초기화 시 복구할 수 없다.
- 인증정보는 복구 대상이 아니다. 매 세션 안전하게 다시 인증하고 로컬 또는 저장소에 남기지 않는다.

## 정상 Clone과 작업 폴더

새 PC에서는 다운로드 ZIP을 안전본으로 먼저 확인하고, GitHub Repository에서 정상 Clone한 `%USERPROFILE%\Iron-Trenches`를 유일한 작업 폴더로 사용한 뒤 그 Clone root를 Codex에서 연다.

```text
새 PC
→ 다운로드 ZIP을 비교용 안전본으로 확인
→ GitHub Repository에서 정상 Clone
→ %USERPROFILE%\Iron-Trenches를 프로젝트 작업 폴더로 사용
→ 그 root를 Codex에서 Open
```

일반 폴더를 만든 뒤 Windows 복사로 파일을 넣고 나중에 Git을 연결하는 방식은 정상 복구로 사용하지 않는다. 다운로드 ZIP과 `Iron-Trenches-main` 형태의 폴더는 Git working copy가 아니라 임시 반입/안전본으로 구분한다. ZIP 폴더에서 개발하거나 Unity 프로젝트를 열지 않는다.

### ZIP 확인과 Clone 전환

1. ZIP은 `Downloads` 아래에서만 풀고 파일 목록, 문서, 예상하지 못한 변경과 Secret 후보를 읽기 전용으로 확인한다.
2. ZIP 안의 실행 파일, 스크립트, Unity 프로젝트와 설치 프로그램을 복구 원본으로 실행하지 않는다.
3. `%USERPROFILE%\Iron-Trenches`가 없을 때만 그 정확한 경로를 Clone Target으로 사용한다.
4. Target이 이미 있으면 삭제·덮어쓰기·재Clone하지 않는다. `.git`, `origin`, branch와 변경 상태를 확인하고 충돌 시 작업을 중단한다.
5. 정상 Clone 뒤 ZIP과 Clone을 비교한다. ZIP에만 있는 변경은 파일별로 검토하고 현재 Result Bundle에 필요한 것만 Clone에 반영한다.
6. `.git`, `Library`, `Temp`, `Logs`, `obj`, IDE 상태, `.codex`, 인증정보와 Secret은 ZIP에서 Clone으로 복사하지 않는다.
7. Codex 연결 폴더를 `%USERPROFILE%\Iron-Trenches`로 바꾸고, 이후 읽기·수정·Unity Open·검증·Commit·Push는 Clone root에서만 수행한다.

ZIP 확인은 원격 Clone을 대체하지 않는다. ZIP과 원격이 같아도 `.git`이 없으면 정상 작업환경이 아니다.

Git CLI 사용이 허용된 경우 다음처럼 고정 작업 root가 아직 없을 때만 Clone한다.

```powershell
git clone https://github.com/SHKK120/Iron-Trenches.git "$env:USERPROFILE\Iron-Trenches"
Set-Location -LiteralPath "$env:USERPROFILE\Iron-Trenches"
.\scripts\restore-session.ps1 -Online
```

기존 변경이 있으면 보존하고 원인을 확인한다. 복구를 이유로 `git reset --hard` 또는 `git clean`을 사용하지 않는다.

고정 Clone 대상 폴더가 이미 있으면 덮어쓰거나 삭제하거나 다른 영구 작업 root를 만들지 않는다. 기존 폴더를 보존한 채 `.git`, remote, branch와 로컬 변경을 검사하고, 정상 working copy가 아니면 사용자 판단 없이 이동·교체하지 않는다.

## 관리형 PC Git fallback

우선순위는 다음과 같다.

1. 정상 Git Clone과 정상 Git workflow
2. 관리형 PC에서 이미 허용된 Git GUI 또는 GitHub Desktop
3. Codex GitHub App / Connector `[읽기·원격 보존 편의 기능, Clone working copy를 대체하지 않음]`

- Git CLI 실행 자체가 `CreateProcessAsUserW failed`, `Access Denied` 등 관리 정책으로 차단되면 반복 실행하지 않는다.
- 관리자 권한 상승, Execution Policy 완화, 다른 binary를 이용한 정책 우회와 보안 기능 비활성화를 금지한다.
- 이미 허용된 Git GUI 또는 정상 GitHub 경로가 있으면 이를 사용한다.
- Git GUI를 사용할 때는 `Clone Existing Repository`에서 Source를 `https://github.com/SHKK120/Iron-Trenches.git`, Target을 `%USERPROFILE%\Iron-Trenches`로 지정한다. ZIP 폴더를 Target으로 재사용하지 않는다.
- Codex GitHub App이 read-only이거나 write 403이어도 정상 Git/GUI가 있으면 프로젝트 개발 자체의 blocker로 간주하지 않는다.
- 모든 원격 쓰기 경로가 불가능하면 새 기능보다 현재 작업의 로컬 보존을 우선하고 `[원격 미보존]`을 기록한다.
- PC 초기화가 임박했고 원격 생존본이 없다면 새 기능보다 허용된 원격 보존을 우선한다.

1. ZIP 안전본을 확인한 뒤 `%USERPROFILE%\Iron-Trenches`에 정상 Git working copy를 확보한다.

`[과거 확인]` 과거 Iron & Trenches 자료에는 Unity / DOTS 기술 방향이 기록되어 있었다. 이는 현재 설치 상태나 적용 시점의 확정이 아니다.

Unity 6.6은 현재 선택한 Supported release다. 지원 상태와 최신 patch는 변할 수 있으므로 새 버전으로 자동 변경하지 말고, 복구 시 공식 지원 상태를 확인한 뒤 프로젝트의 `ProjectSettings/ProjectVersion.txt`가 요구하는 정확 버전을 설치한다.

Unity Hub와 Unity Editor는 항상 일반 사용자 권한으로 실행한다. `Administrator Privileges Detected`가 표시되면 `Ignore Warning`을 선택하지 않고 `Restart as Standard User`를 선택한다. 같은 경고가 다시 표시되면 Editor만 반복 재시작하지 않는다. Hub 창을 닫는 것만으로는 백그라운드 Hub 프로세스가 남을 수 있으므로, 알림 영역의 Unity Hub 아이콘에서 Hub를 완전히 종료한 뒤 바탕 화면 또는 시작 메뉴에서 `관리자 권한으로 실행`이 아닌 일반 실행으로 다시 연다. 바로가기와 실행 파일의 호환성 설정에 `관리자 권한으로 이 프로그램 실행`이 켜져 있다면 사람이 승인된 PC 설정 절차로 해제하며, 보안 설정이나 UAC를 우회·비활성화하지 않는다.

Hub를 완전히 종료·재실행한 뒤에도 경고가 반복되고 바로가기의 관리자 실행 플래그가 꺼져 있으며 실행 파일 manifest가 `asInvoker`라면, 현재 Windows 로그인 세션 또는 시설 정책이 관리자 토큰을 부여한 상태로 판정한다. 이때 재시작 버튼을 반복하거나 UAC·보안 정책을 변경하지 않는다. 작업을 중단하고 PC 재부팅 뒤 일반 실행을 다시 확인하며, 그래도 반복되면 표준 사용자 계정 사용 또는 시설 관리자 지원이 필요하다고 기록한다. 관리자 경고를 무시한 실행은 자동 복구 절차에 포함하지 않는다.

사용자가 명시적으로 현재 세션의 진단 실행을 승인해 경고를 넘긴 경우에도 이는 복구 기본 절차로 승격하지 않는다. 해당 실행은 프로젝트 Open과 Compile 가능 여부만 확인하고, 보조 프로세스·named pipe·Compile 오류가 발생하면 즉시 종료해 실제 실패 원인을 기록한다.

## 초기화 PC 도구 설치 순서

도구 설치는 다음 순서로 한 번씩만 수행한다.

1. 정상 Clone 또는 승인된 원격 작업 환경을 먼저 확보한다.
2. Unity 공식 배포 경로에서 Unity Hub를 기본 경로에 설치한다.
3. Hub에서 Unity ID 로그인과 License 활성화를 사람이 완료한다. 인증정보는 문서나 저장소에 남기지 않는다.
4. Hub의 `Installs`에서 `6000.6.0f1`을 선택하고 기본 Editor 경로에 Windows Standalone Support와 WebGL Build Support를 설치한다.
5. Microsoft 공식 Visual Studio Community 설치 프로그램을 실행하고 기본 경로와 `Unity를 사용한 게임 개발` workload를 선택한다.
6. Hub와 Visual Studio 양쪽에서 같은 도구를 중복 설치하지 않는다. Hub가 이미 있으면 Visual Studio 선택 구성의 Unity Hub는 제외하고, Visual Studio가 이미 있으면 Hub의 Visual Studio 선택 구성은 제외한다.
7. 설치 후 이 문서의 실제 경로 확인과 `restore-session.ps1` 또는 Q0 수동 검사를 수행한다.
8. Hub와 Editor를 일반 사용자 권한으로 실행한다. 관리자 권한 경고가 반복되면 Hub를 알림 영역에서 완전히 종료하고 일반 실행으로 다시 시작한 뒤 프로젝트를 연다.

공식 다운로드 원본:

- Unity Hub: `https://unity.com/download`
- Unity Editor 6000.6.0f1: `https://unity.com/releases/editor/whats-new/6000.6.0f1`
- Visual Studio Community: `https://visualstudio.microsoft.com/downloads/`

설치 파일 자체는 Git에 보존하지 않는다. 초기화 뒤 위 공식 원본에서 다시 받고, 경로 또는 버전이 달라지면 실제 확인 뒤 이 문서와 검사 스크립트를 같은 Checkpoint에서 함께 갱신한다.

Hub 설치만으로 Editor가 즉시 자동 설치되는 것은 아니다. Hub 설치 뒤 Editor 버전과 모듈을 명시적으로 선택해야 하며, 프로젝트 생성은 Editor 설치와 별도 단계다.

관리형 PC에서 설치 프로그램이 차단되면 관리자 권한, 보안 설정 또는 실행 정책을 우회하지 않는다. 공식 설치 프로그램과 이미 허용된 GUI만 사용하고 실패 항목을 `[BLOCKED — 관리형 PC 정책]`으로 기록한다.

- 정확 버전: `[확인 사실] 18.10.12201.205`
- 설치 위치: `[확인 사실] C:\Program Files\Microsoft Visual Studio\18\Community`
- 필수 workload: `[확인 사실] Microsoft.VisualStudio.Workload.ManagedGame — Unity를 사용한 게임 개발`
- 필수 component: `[확인 사실] Microsoft.VisualStudio.Component.Unity — Visual Studio Tools for Unity`
- Installer 위치: `[확인 사실] C:\Program Files (x86)\Microsoft Visual Studio\Installer\setup.exe`

설치 완료 시 `Microsoft.VisualCpp.Redist.14` 경고가 발생했지만 Visual Studio 본체, Unity workload와 Unity component는 설치 등록됐다. `vcruntime140.dll`과 `msvcp140.dll`은 System32와 SysWOW64에 존재했다. DLL 존재만으로 runtime 정상 동작을 확정하지는 않는다. 이 경고만 보고 보안 정책을 우회하거나 반복 설치하지 않고, Visual Studio 실행 또는 Unity Compile이 실패할 때만 Microsoft 공식 Visual C++ Redistributable 복구/수정을 승인된 경로로 수행한다.

## Unity MCP 복구 규격

- Unity 프로젝트가 생긴 뒤 Unity MCP 1개를 선택한다.
- 공식 Unity MCP가 당시 프로젝트 조건에서 사용 가능하면 우선 검토한다.
- 공식 MCP가 불가능하면 승인된 대체 Unity MCP 하나를 사용한다.
- Unity MCP 두 종류를 동시에 기본 활성화하지 않는다.
- 현재 Unity MCP: `[미구성]`

실제로 선택된 뒤 이 문서에 다음을 기록한다.

- MCP 이름과 정확 버전 또는 기준 commit
- 지원 Unity 버전
- 설치 위치와 등록 방법
- `.codex/config.toml` 재구성 방법
- Editor 측 설정과 서버 시작 방식
- 허용 tool과 금지 또는 승인 필요 tool
- Codex 재시작 필요 여부
- Smoke 호출과 정상 결과

설정 파일 존재만으로 연결 성공 처리하지 않는다. Unity Editor 실행, 실제 MCP 연결, 현재 Scene 조회, Console 조회, GameObject 또는 Component 조회까지 실제 호출한 뒤 복구 성공으로 판정한다.

Unity 프로젝트 생성 전에는 Unity 관련 단계가 적용되지 않는다.

PowerShell 실행 자체가 정책으로 차단되면 Execution Policy 변경, 다른 PowerShell binary, 관리자 실행 또는 AppLocker 우회를 시도하지 않는다. `[BLOCKED — 관리형 PC 정책]`으로 처리하고 같은 Q0 항목을 수동으로 확인한다. `restore-session.ps1`이 없어도 이 문서만으로 복구할 수 있어야 한다.

## 세션 종료 전 생존 확인

- `git status --short --branch`로 남은 변경을 확인한다.
- 현재 Result Bundle에 포함되는 파일만 명시적으로 stage한다.
- Secret과 개인 설정이 포함되지 않았는지 확인한다.
- 기술 검증과 필요한 사람 확인을 분리해 기록한다.
- 승인된 Checkpoint를 commit하고 `origin/main`에 push한다.
- local `HEAD`와 `origin/main`이 같은지 확인한다.
- 완료된 Checkpoint와 다음 재개 지점을 `40_구현순서.md`와 `지시장부.md`에 남긴다.

세션 종료 전에 push되지 않은 로컬 변경은 임시 작업으로 취급하며 복구를 보장하지 않는다.
