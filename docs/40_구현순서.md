## 운영 제약

- 현재 Codex 작업 폴더는 `.git`이 없는 `Iron-Trenches-main` 임시 반입/안전본이다.
- 고정 작업 root `C:\Users\CKIRUser\Iron-Trenches`의 정상 Clone은 완료됐고 이번 문서·스크립트 변경 4개도 반영됐다. Codex 연결 전환은 아직 필요하다.
- 관리형 PC 정책으로 Git CLI 프로세스 실행이 `Access denied` / `EPERM`으로 차단됐다.
- Git GUI 실행 파일은 존재한다.
- Codex GitHub App은 pull / push 권한을 표시했지만 실제 Contents 쓰기는 403으로 거부됐다.
- Git GUI Clone, Stage, Commit과 `origin/main` Push를 완료했다. `Index Error` 표시는 실제로 LF→CRLF 줄바꿈 경고였다.
- Unity Editor의 관리자 권한 경고가 Hub 완전 종료·재실행 뒤에도 반복됐다. 바로가기 관리자 플래그는 없고 Hub/Editor manifest는 `asInvoker`이므로 Windows 로그인 세션 또는 시설 정책의 관리자 토큰 가능성이 높다.
- 정상 Clone 안의 `Game` 프로젝트는 Editor와 SampleScene까지 열렸지만 Bee가 `cmd.exe` / Unity 내장 `dotnet.exe`를 시작하지 못해 Compile Error 0을 통과하지 못했다. Hub는 총 RAM 4GB 미만 경고도 표시했다.

## Blocker

Unity Editor는 열리지만 관리형 PC 정책이 Unity Bee의 필수 자식 프로세스 실행을 `GetLastError 5 (Access denied)`로 차단한다. Compile Error 0과 Play Smoke가 없으므로 DEV-BOOT 기술 Baseline을 완료 처리하지 않는다.

1. 현재 `Game/` 재현 파일과 실제 Compile blocker 기록을 환경 Checkpoint로 보존한다.
2. 시설 관리자에게 Unity Editor, Bee backend, `cmd.exe`와 Unity 내장 `dotnet.exe` 자식 프로세스 실행 허용을 요청하거나 정책 제약이 없는 PC에서 연다.
3. Compile Error 0 → SampleScene Load → Play → Stop → Editor 재실행 Smoke를 실제로 통과시킨다.
